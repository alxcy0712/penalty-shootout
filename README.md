# 十一码之夜

原创手机竖屏点球游戏，含简洁版与高级版。使用 Vite、原生 JavaScript 和 Three.js；球场、球网、足球和观众由本地代码生成；人物采用本地 GLB 蒙皮模型与动捕素材，来源见 [素材署名](public/character-credits.txt)。游戏无需账号或网络游戏服务。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
```

打开 http://localhost:5173/。电脑默认显示竖屏容器；手机与电脑在同一局域网时，可访问终端显示的 Network 地址。服务器运行期间保持终端开启。

```sh
npm test       # 规则、属性、输入与物理回归测试
npm run build # 输出 dist，可部署为静态网页
npm run preview
npm run qa:release:plan # 查看固定的完整验收计划，不代表通过
npm run qa:release      # 串行完整验收，磁盘输出，可耗时较长
```

## 操作

- 简洁版：点击锁定左右方向，再点击锁定力度；射门不限时。守门点击左、中、右，AI 在准备后 3 秒出脚。
- 高级版：从足球附近向上滑动，横向偏移决定方向，上划距离决定高度与力度，松手前可回拉减力，弯曲手势增加旋转；鼠标按住左键拖动等价。准备后 10 秒未有效出脚，自动最轻力度射向中路。
- 守门可提前预判，根据来球时间调整起扑时机；未选默认中路。高级版左右滑动即可，速度不影响扑救。已经侧扑后方向锁定。
- 首页“力度校准”支持鼠标、触屏和笔分别设置；新校准按上划像素距离统一计算比赛力度，满力度距离越低，短划越容易发力。三次试滑只生成草稿，点击保存才提交当前设备。旧设置保持原手感并提示重新校准；若满力度距离超过当前操作区域，准备页提供校准入口。布局改变或失焦会取消当前手势，重新划动即可。
- 高级版赛前可调整全部 11 人的罚球顺序，点击球员查看属性。位置为 4 后卫、3 中场、3 前锋、1 门将；所有人都能罚球，守门固定门将。
- 成功保存后，暂停、返回首页或刷新可继续本地进度。写入失败会明确提示“仅本页保留”，本页Home仍可继续，但关闭/刷新可能丢失最新进度。新比赛覆盖未完成进度前会确认；取消不写入。浏览器清理站点数据会清除持久进度与校准。

## 加载与图形恢复

人物加载期间会显示状态并暂缓下一脚。资源失败后可以使用明确标注的简化模型或基础动作继续，在首页、准备或结果阶段重试。图形连接丢失时比赛与输入冻结；浏览器恢复且首次重绘返回后，点击“继续显示”，原有暂停仍保留。无法恢复时可刷新，最新进度能否保留以保存提示为准。

`?profile`开启诊断，前台长帧不会被丢弃；隐藏、加载/图形中断、主动暂停分别统计。百分位标注为上界估计，CPU更新/提交不代表GPU时间。[A2开发契约](docs/A2_DEVELOPER_GUIDE.md) · [完整QA入口](tools/qa/RELEASE_QA.md)

## 玩法与判定

五轮交替主罚，优势已无法追平时提前结束；五轮平局进入突然死亡，双方完成同等罚球次数后决胜。全员罚过一次才开始下一轮人员循环。掷币决定先后罚选择权。

所有能力上限 99，门将接球稳健性为 90–99。准度影响偏差，脚力影响球速，心理影响关键轮次发挥，触球控制影响稳定性，大力射门的打飞概率由准度、稳定性、心理和脚力共同决定；高级版的弧线能力影响旋转；扑救速度、覆盖范围和接球稳健性参与门将运动与接触结果。高稳健性仍受接球部位和球速影响。

AI 在每脚开放操作前决定方向与射门意图。简洁版 AI 扑左、中、右等概率。物理引擎采用 120 Hz 固定步长，包含重力、地面反弹、摩擦、门框、门将蒙皮表面包络接触、抱球与反弹。足球整体越过门线才得分；扑球后反弹入网有效，无补射。

本项目覆盖点球决胜的可玩核心规则。固定 11 人，无伤停、罚下、换人、裁判犯规与重罚等赛事管理系统。画面为原创风格化三维模型，竖屏 2.5D 镜头。

## 人物与动作

唯一动作验收入口为 [motion-lab](http://localhost:5173/motion-lab.html)，正式游戏为 [5173 首页](http://localhost:5173/)。两边共用 `GameCharacter`、同一套蒙皮映射和动作实现：

- 射手：`assets/characters/striker-mocap.glb`，CMU 助跑、射门与随摆，原素材触球标注约为 1.85 秒；运行时按真实鞋面校准到 1.8467 秒。整段助跑随目标方向绕足球转向；低平球、勺子球和力度使用保留触球与支撑脚的程序化随摆修饰。片段末尾补充落步收势，避免截断后悬脚。这些修饰不是新的动捕素材。
- 门将：`assets/characters/keeper-prototype.glb`，由 `anatomy.js` 的程序姿态驱动；手腕、肘、膝和脚踝与比赛碰撞骨架一致。运行时增加两个肩部变形辅助骨（总计 24 骨）保持抬臂体积；撑地时按实际手套包围范围修正腕角，保持腕关节目标。肩肘权重跨材质接缝平滑，防止袖口薄片和裂缝。起身先收下侧支撑脚，再让上侧脚越过并落地，避免双小腿、鞋底互穿。
- 接球：刚性手套使用真实三角面，肩袖/肘部保留动态蒙皮接触片；收球时球、掌心与双臂一起求解，比赛和检查页使用同一条连续路径。
- 球衣区分阵营与位置：我方浅绿、对方珊瑚橙，我方门将蓝、对方门将金黄。
- 球场保留比赛灯光与镜头；动作检查页独立自适应布局，支持正面、侧面、斜侧、背面、分屏、缩放、面部近景、线框及实际骨架叠加。可跳至触球/关键阶段、以 60 Hz 检查步长前后逐帧、半速/四分之一速度或循环播放。手机窄屏默认大单视图，分屏时上下排列。

GLB 加载失败时，`character.js` 提供程序人物备用显示，同时提供球衣号码素材。这是仍在使用的依赖。同类 GLB 只解析一次，各人物使用独立骨架和球衣材质；加载完成后恢复最新动作，不重新跳回预备姿态。球路始终按比赛物理计算。桌面数值/离屏验收记录见 [验收说明](VALIDATION.md)；真实手机 GPU 性能、触屏手感和浏览器实机画面仍需对应设备确认。

## 项目结构

- `src/main.js`：流程、输入、音效、暂停与存档。
- `src/engine.js`：比赛规则、球员能力、物理和接触判定。
- `src/scene.js`：球场、灯光、镜头与人物调度。
- `src/game-character.js`：正式游戏与动作检查页共用的人物加载和动画。
- `src/anatomy.js`：固定骨长、IK、门将和射手程序姿态。
- `src/keeper-skin-pose.js` / `keeper-arm-roll.js`：蒙皮骨骼映射、肩部体积与手臂修正。
- `src/keeper-skin-weights.js`：保持材质接缝焊接的肩肘局部权重平滑。
- `src/keeper-hand-contact.js`：保留物理腕关节点的手套朝向与地面接触修正。
- `src/keeper-contact.js` / `keeper-contact-data.js`：由当前模型生成的表面碰撞、动态蒙皮接触片和连续掌心收球。
- `tools/qa/`：可复现的真实蒙皮导出、Blender 离屏渲染、接触矩阵、净空与自交审计。
- `src/striker-kick-style.js`：动捕上的射门方式修饰、固定骨长腿部 IK 和落步收势。
- `src/motion-lab-runtime.js` / `motion-lab-state.js`：共享人物的检查工具与可独立测试的时间线状态。
- `assets/characters/`：当前 GLB、Blender 制作文件、必要中间文件和来源许可。
- `tools/`：当前人物的制作、采样与修复脚本，见 [制作文件说明](BLENDER文件说明.md)。
- `tests/`：规则、物理、人物资产与动作一致性回归。

构建同时输出游戏和动作检查页。开发服务固定使用 5173；端口占用会直接报错。若页面与源码不符，停止旧 Vite 进程后重新启动，并检查 `/src/scene.js` 响应确实使用 `GameCharacter`。

本地检查包括 `npm test`、`npm run build`、浏览器实际加载和比赛流程。已删除旧原型入口、旧模型版本与历史截图；需要追溯时查看 Git 历史。
