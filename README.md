# 十一码之夜

原创手机竖屏点球游戏，含简洁版与高级版。使用 Vite、原生 JavaScript 和 Three.js；球场、人物、球网、足球、观众与动作均由本地代码生成，无外部素材、账号或网络游戏服务。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
```

打开终端显示的地址。电脑默认显示竖屏容器；手机与电脑在同一局域网时，可访问终端显示的 Network 地址。服务器运行期间保持终端开启。

```sh
npm test       # 规则、属性、输入与物理回归测试
npm run build # 输出 dist，可部署为静态网页
npm run preview
```

## 操作

- 简洁版：点击锁定左右方向，再点击锁定力度；射门不限时。守门点击左、中、右，AI 在准备后 3 秒出脚。
- 高级版：从足球附近向上滑动，横向偏移决定方向，上划距离决定高度与力度，松手前可回拉减力，弯曲手势增加旋转；鼠标按住左键拖动等价。准备后 10 秒未有效出脚，自动最轻力度射向中路。
- 守门可提前预判，根据来球时间调整起扑时机；未选默认中路。高级版左右滑动即可，速度不影响扑救。已经侧扑后方向锁定。
- 首页“力度校准”支持鼠标和触屏分别设置；满力度拖动距离越低，短划越容易发力。可完成三次舒适手势自动校准。
- 高级版赛前可调整全部 11 人的罚球顺序，点击球员查看属性。位置为 4 后卫、3 中场、3 前锋、1 门将；所有人都能罚球，守门固定门将。
- 暂停、切换页面、刷新后可继续本地进度。浏览器清理站点数据会清除进度与校准。

## 玩法与判定

五轮交替主罚，优势已无法追平时提前结束；五轮平局进入突然死亡，双方完成同等罚球次数后决胜。全员罚过一次才开始下一轮人员循环。掷币决定先后罚选择权。

所有能力上限 99，门将接球稳健性为 90–99。准度影响偏差，脚力影响球速，心理影响关键轮次发挥，触球控制影响稳定性，大力射门的打飞概率由准度、稳定性、心理和脚力共同决定；高级版的弧线能力影响旋转；扑救速度、覆盖范围和接球稳健性参与门将运动与接触结果。高稳健性仍受接球部位和球速影响。

AI 在每脚开放操作前决定方向与射门意图。简洁版 AI 扑左、中、右等概率。物理引擎采用 120 Hz 固定步长，包含重力、地面反弹、摩擦、门框和门将胶囊碰撞、抱球与反弹。足球整体越过门线才得分；扑球后反弹入网有效，无补射。

本项目覆盖点球决胜的可玩核心规则。固定 11 人，无伤停、罚下、换人、裁判犯规与重罚等赛事管理系统。画面为原创风格化三维模型，竖屏 2.5D 镜头。

## 动画与性能验收

人物使用固定骨长和双骨 IK，助跑时右脚先支撑、左脚落地后右腿摆动，支撑脚保持固定；踢球脚在触球前后保持速度连续，力度影响摆腿速度；射门意图方向影响躯干转向、球鞋朝向和随摆轨迹，偏向两侧时仍保持支撑脚固定；侧扑腾空使用重力轨迹，并向前移动以避开门柱，落地后先保持肩侧支撑、沿弧线收腿落脚，再转移重心、撑地起身；中路防守会随来球高度抬手收拢，反应时机受扑救速度影响；中途选择侧扑从当前姿态衔接；起跳后保持既定侧扑轨迹，结果动画继承最后反应高度，避免反弹球引起身体或手臂瞬移。接稳球后延续原有肘部弯曲方向，双手随球平滑收向胸前，侧卧时避开草坪侧的关节翻转；头部在颈部角度限制内平滑追踪足球。测试还扫描实际模型顶点，检查手套、球鞋与身体表面是否穿过草坪或门柱，并检查落地后的整个人物是否悬空。进球后延续实际球速，重力、草地与球网碰撞负责减速，球网从接触位置产生衰减波动。角色仍采用原创程序化建模，与商业足球手游的扫描角色、蒙皮形变和动作捕捉存在差距。

最近一轮电脑复核：主页约 60 FPS、帧间隔均值 16.67 ms / P95 18.20 ms、64 次绘制；比赛结果场景约 60 FPS、均值 16.67 ms / P95 18.80 ms、105 次绘制、106/115 几何体、5 张纹理。这是短窗口观察值，不能替代持续压力测试或真机结果。固定待机门将姿态在场景创建时计算一次，后续帧复用骨架数据，减少重复 IK 和临时对象创建。

玩法修正：简洁版方向游标在中央较慢、接近两端加速，端点立即折返；低力度射门采用贴地推射，随力度增加平滑过渡到腾空轨迹。门将中路低球会下蹲，球鞋纳入碰撞；身体碰撞使用首次接触表面的反弹法线并按接触先后处理，避免足球深入模型后才反弹。方向正确仍需在球经过时实际接触，擦边反弹入网继续按进球处理。


本轮玩法调整：简洁版方向条周期为 2.4 秒，边角区域加速；轻推初速约 4.8 m/s，草地滚动减速度 0.8 m/s²。门将预判后按可达范围选择起扑时机，慢球允许更充分准备；扑救仍由球与实际骨架碰撞判定。每脚结果页和最终赛果页均可直接返回首页。顶部盾牌入口可随时暂停查看双方球员能力。

攻守使用相反方向的镜头，换边环绕过渡；守门左右操作按屏幕方向映射。高级版收起球员栏与冗余界面，拖动时显示一段空间轨迹弧线，松手发球。弧线为方向提示，保留实际触球误差；弯划方向和球员弧线能力共同决定空中侧向旋转。支持系统减少动态效果设置。

门将等待慢球时先向预判方向小步调整并压低重心，再平滑衔接侧扑；球速达到 23 m/s（约 83 km/h）时立即启动侧扑。准备姿态与扑救判定共用同一套骨架。


门将追球与死角扑救：所有追球移动均在足球被踢出后开始；出脚前维持门线站位，球鞋与门线相交。出脚后经过能力相关的反应时间，按当前球的位置和速度横移、小幅迎球，使用有速度和加速度上限的交替步伐。能走到的近身球优先下蹲封堵；已经腾空的侧扑保持方向，落地起身后可重新追球。松散反弹球仍可继续拦截，球整体越过门线立即计分。规则依据：[IFAB 第14章](https://theifab.com/laws/latest/the-penalty-kick/)。

远角根据距离和扑救范围能力触发更充分的起跳、展体和伸臂；肩、肘、膝的固定骨长保持不变，手套真实接触足球才算扑到。动作检查页新增“死角伸展扑救”。`tests/keeper.test.js` 覆盖门线初始站位、反应延迟、540 组近身慢球、远角速度差异、扑错边后的恢复、动作连续性及追球存档恢复；实际模型测试包含伸展和移动姿态的草坪与门柱穿透检查。

错边中断动作：出脚后观察到较快来球明显朝另一侧飞行、且门将仍在起扑支撑阶段时，门将会收回伸手、压住重心，短暂停顿后站稳；视线继续由来球驱动。充分腾空后维持原有轨迹，慢球保留追踪调整。此动作与碰撞共用骨架，动作检查页可选择“判断错边收住动作”。

扑出后的收尾：离开门前并持续远离球门的反弹球会停止触发追踪，门将在扑救位置完成起身；中路低球封堵后也会逐步放松并站稳。对于已经越过所有可接触物体、在当前物理模型中无法返回球门的远球，使用 8 倍尾段播放并显示“尾段快进”；判定仍模拟至足球停止或出界。门将动画采用独立的显示时间，保持原速落地和起身。移动姿态加入小幅躯干重心倾斜，收势时平滑回正，并完成已开始的落脚动作。人物继续使用程序化骨骼动画。
