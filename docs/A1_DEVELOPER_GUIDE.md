# A1 二次开发指南

本阶段把输入单位、手势生命周期和存储结果从页面流程中拆开；并为模型制作建立候选边界。它不是通用游戏框架，也没有改变比赛物理或正式资产。

## 入口与责任

- `src/calibration.js`：设备配置校验、旧值适配、校准草稿和手势力度映射；不读DOM或Storage
- `src/gesture-session.js`：一个指针事件序列的坐标/设备/配置快照；布局变化使本序列失效
- `src/persistence.js`：存储通道、结构化读写结果、会话快照与旧版比赛恢复边界；详见 [存储契约](PERSISTENCE_CONTRACT.md)
- `src/main.js`：弹层、提示、暂停、开始/继续比赛和各模块的调用顺序；不复制第二套力度计算
- `tools/model-build/`：离线候选工具，能力与提升限制以该目录的说明为准；不可把编辑副本当作原始制作历史

设计原因与未解决边界见 [ADR](architecture/ADR_A1_FOUNDATION.md)。研究报告保留为修复前证据，不应将其中重现旧缺陷的脚本当作修复后的发布测试。

## 添加输入方式或校准参数

先决定数据的单位与版本，再添加控件。新像素校准只替代高级手势的力度映射；方向、目标高度与弧线仍按游戏区域归一化。不要为了“统一”悄悄改动 `engine.gestureInput`，旧配方、测试和legacy适配仍依赖其既有含义。

新设备要补配置默认、有限值/范围校验、UI选择和设备隔离测试。读取旧偏好不应自动写盘；未知未来版本不能被一次普通设置修改降级覆盖。保存新校准是显式提交，打开/关闭弹层不是提交。已存CSS像素距离不能随窗口尺寸变动自动改写；若超过当前操作区域，准备阶段应提示重新校准。

一次手势只拥有一个指针ID、元素和坐标快照。新输入事件路径必须经过同一取消逻辑，处理布局变化、暂停、失焦、旧元素事件和指针取消。不能靠放宽数值范围掩盖把布局位移当手指位移的问题。

## 添加存档字段或续玩模式

保持保存格式和运行时对象职责分离。`Match.restore` / `Shot.restore` 是内部可信数据原语；浏览器存档等外部数据必须先经过 `restoreMatchSave` 的版本/结构/可赋值字段边界，不能直接交给类实例的 Object.assign。当前比赛沿用version1完整JSON，避免挑选字段丢失RNG、接触冷却、恢复起点或展示钟。当前v1的Match/Shot根数据字段采用明确白名单；未知字段会拒绝续玩并保留原数据，不会悄悄丢弃。新增字段时明确旧数据缺省和迁移；若变更含义，应增加格式版本和迁移测试，不只是给缺字段补零。

写入成功、在本页可继续、磁盘旧副本仍存在是三件不同的事。UI不能用读成功替代写成功，也不能让偏好写失败污染比赛通道。新建覆盖确认之前不写任何新局；取消保持磁盘与会话数据。恢复在副本上执行，失败不部分污染当前比赛。

测试至少包含：写入拒绝→继续本页→Home→恢复；失败后重试成功；损坏JSON；未来版本；取消覆盖；中途飞行的旧version1恢复后与原轨迹一致。真实浏览器禁用存储、配额和跨页面行为仍需设备层测试。

## 制作新模型或动作

不要直接在正式 `assets/characters` 上运行旧rebuild。先确认输入是制作源还是从GLB重建的编辑副本、工具版本、输入hash、源动作和接触事件。候选输出、校验、提升是不同步骤，格式正确不等于美术和碰撞正确。

A1工具的安全能力边界必须保持：改变几何的候选缺少固定深度验收适配时禁止提升；不能填一条外部“passed”来绕过。下一阶段要扩展生成适配器，应先在隔离目录接固定命令与固定文件集合，再把完整球/皮肤/连续性验收和人工同镜头视觉审核纳入产物身份。不要开放清单执行任意shell命令。

正式资产升级应作为一批相关产物审查：GLB、可编辑副本、元数据、碰撞缓存、来源与验证记录。多文件发布的日志/回滚是可恢复事务，不是文件系统跨文件原子承诺；出现中途失败先根据日志恢复，不要覆盖后来别人的修改。

## 推荐验证层级

1. 改纯输入/存储函数：跑对应单元测试与真实main事件harness，保留旧配置/旧存档路径
2. 改页面协调：补中断和重复事件，跑所有移动输入/生命周期/恢复测试；不要仅比较最终分数
3. 改制作工具：测试不支持环境在写入前失败、来源/输出篡改、部分提升恢复、正式资产不变
4. 交付前：全测试与构建，检查正式资产和物理源hash；固定射门配方可用 `tools/qa/audit-a1-physics-contract.mjs --before <干净基线目录> --out <证据目录/physics.json>` 比较完整终局Shot
5. 修改存档字段时，运行 `node tools/qa/audit-persistence-schema.mjs --out <证据目录/schema.json>`；它对既有669球的过程/终局快照检查版本边界与完整恢复，不只验证构造器初始字段
6. 只有模型/接触/动作变更，才必须重新跑对应的全皮肤与几何门禁；不能拿旧hash收据证明新模型

本次事件/DOM替身证明逻辑，不证明手机触感、屏幕布局或WebGL稳定性。A2将处理加载/图形中断与实机档案，不应由A1的测试通过推断已经完成。
