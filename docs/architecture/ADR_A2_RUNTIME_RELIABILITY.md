# A2 运行状态与验收入口设计

基线：研究分支884c0347ef5126c5f17df0d37197448c46163315。目标是让测量、资源就绪和图形中断有可测试的契约；沿用A1输入/存档边界，不修改比赛物理和正式资产。

## 实施前决定

1. 性能采样来自原始rAF时间，不使用被物理限幅后的dt。保留所有有限正前台间隔，包括超过250ms的卡顿；隐藏、图形中断和有意停止动画另记状态，不把跨状态空档算成前台卡顿。CPU提交时间不是GPU时间。只在profile开启时收集，有界窗口，UI至多每秒更新。
2. 每个角色拥有加载代次、就绪/降级/失败状态及实例资源；共享源缓存不归单个角色释放。失败不默默冒充就绪；超时与迟到结果不得重复安装模型。重试仅在稳定比赛边界提供，加载期间不开始下一脚，原进度保留。程序模型回退可继续，但明确提示与重试入口。
3. 图形中断使用独立控制器与锁，不复用用户暂停布尔值。lost事件立即阻止默认行为、取消手势、停止比赛钟和渲染；浏览器restored事件才表示可以尝试重绘。恢复不启动第二个rAF循环，不自动结束已有暂停；超时保留刷新/返回指引。不调用强制恢复扩展掩盖浏览器拒绝。
4. 权威发布验收采用版本化固定清单、固定命令与来源hash。计划展示不算通过，所有失败收据保留；默认磁盘输出及串行重检查，避免tmpfs和并发内存尖峰。669球/223接球及可见手指/拇指变形必须进入完整路径。

## 代价与边界

状态模块不是通用框架。加载成功后的正常逐帧路径只增加简单状态判断；资源回收和汇总在事件边界执行。不会借此承诺手机FPS或真实WebGL恢复已验证；Node事件故障注入和CPU几何验收与真机验证分别记录。实际驱动恢复、冷网络和移动设备矩阵仍需后续实机层验证。
