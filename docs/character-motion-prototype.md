## 原实现诊断

- **人物轮廓与变形：** `src/character.js`、`src/anatomy.js` 以程序几何和连续肢体表面生成角色；IK 使用固定的 `0.43 m` 大腿与小腿、`0.29/0.27 m` 上下臂长度。弯肘弯膝会逐帧更新四肢顶点和法线，肩颈、躯干与短裤仍由若干独立几何相接。主要风险是关节弯折时体积损失、肩部接缝和球衣/短裤边缘。
- **动作节奏：** 动作由公式、IK、姿态混合与物理步间插值驱动。角色动画不是刚体物理求解；如果关键姿势、支撑点和触球时刻没有约束，根部移动、脚底滑动、惯性和触球会彼此脱节。
- **运行成本：** 旧角色单体约 27 个网格对象、22,120 个顶点、36,818 个三角形；现有肢体变形会更新 JavaScript 顶点和法线。基线的 181 个动作样本在本机 Node 测得均值约 `0.156 ms`、P95 约 `0.543 ms`，仅用于代码级参考，不代表浏览器或手机帧时。此前生产构建主 JavaScript 为 `601.14 kB`（gzip `162.24 kB`），Vite 报出 500 kB 分块提示。

原型保留物理骨长与球的 `Shot` 逻辑。踢球动画的支撑脚锁定在触球前落地，并在触球后短暂保持；落脚到触球的时段沿用研究观察到的近中点关系。带蒙皮的 GLB 负责动作节奏和身体整体传力，页面侧用轻量姿势修正转向、球路和力度；球的位置与结果仍由比赛的物理逻辑计算。

## 原型采样结果

2026-09-25，Chrome 桌面视口 `1440×722`、DPR `2`、渲染比 `1.70`。正常速度播放中两名角色、球、地面和网格合计峰值约 `44` 次绘制、`54,956` 个三角形；角色动作更新约 `0.20 ms`，本次球路预演计算 `2.50 ms / 56` 个固定步，之后缓存复用。GLB 单次加载约 `112 ms`、解析约 `3.9 ms`。短片段帧间隔 P50/P95 为 `16.7/17.1 ms`，未记录超过 `33.3 ms` 的帧。

Chrome 手机视口模拟覆盖竖屏 `390×844` 与横屏 `844×390`，两者 DPR 与渲染比均为 `1`；短时帧间隔 P50/P95 为 `16.7/18.6 ms`，未记录超过 `33.3 ms` 的帧。浏览器连续重新进入三次后，WebGL 资源计数每次为 `36` 个几何体、`4` 张纹理；等待约 `1.1 s` 后 JS heap 每次读数为 `16 MB`。立即采样曾在 `25–43 MB` 间波动，等待后回落；Chrome 的 heap 指标也会覆盖同一渲染进程中的页面分配。

回归检查逐帧核对左右腿骨段与现有 `body.thigh/body.shin` 的长度差小于 `15 mm`，检查支撑脚在锁定段内与目标偏差小于 `25 mm`，并对该段 GLB 蒙皮包围盒检查穿地和异常拉伸。Three.js 浏览器模拟覆盖布局和短时帧间隔；真机加载、发热/降频、较弱设备 30 fps 档位与长时间内存行为仍待验收。

## 研究依据

- 2024 年足球踢球三维运动分析观察支撑脚触地、髋/骨盆和踢球腿近端到远端的时序：[研究论文](https://eprints.chi.ac.uk/7312/1/Multiplanar%20lumbar%2C%20pelvis%20and%20kick%20leg%20sequencing%20during%20soccer%20instep%20kicking%20from%20different%20approach%20angles%20%282024%29%20Augustus%2C%20Hudson%2C%20Smith.pdf)。
- 支撑脚应跨过动作过渡保持约束，并避免逐帧 IK 独立求解引发接触漂移：[Footskate Cleanup](https://research.cs.wisc.edu/graphics/Gallery/kovar.vol/Cleanup/)。
- 足背踢的助跑、支撑脚落位和近端到远端加速关系见运动生物力学综述：[综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC3786235/)。
